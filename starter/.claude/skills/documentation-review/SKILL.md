# Documentation review

- Check changed text for clarity, consistency, broken formatting, and actionable instructions.
- Compare claims and examples with the supplied context; do not assume unavailable behavior or configuration.
- Treat prose and non-executable examples as documentation, not executable code. Do not invent test gaps or code refactorings for them.
- Identify documentation gaps only when the supplied evidence supports them. Follow the invoking specialist's output schema and scope.
